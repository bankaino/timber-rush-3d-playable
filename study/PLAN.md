# Timber Rush 3D — план и журнал решений

## Зачем
2D-версия Timber Rush (bankaino/timber-rush-playable) сделана спрайтами, а референс (реклама лесозаготовки) — настоящее 3D.
Цель: та же игра в настоящем 3D, но с ценой и скоростью HTML5-пайплайна (один файл ≤ 2 МБ под все сети), без Unity в цикле.
Заодно это проверка собственных скиллов (three.js).

## Решения
| вопрос | решение | почему |
|---|---|---|
| движок | three.js (r186), тришейкинг под игру | 0,68 МБ против 1,4 МБ Luna-пакета; Claude хорошо пишет three.js; итерация — перезагрузка страницы, а не сборка Unity |
| логика | `live/sim.js` из 2D-версии без изменений | правила, демо-плеер, idle-правила, A/B-параметры уже отлажены; 3D — только новая отрисовка |
| мир | процедурно в коде: харвестер, прицепы, ели, пни, площадка | 0 байт ассетов, полный контроль силуэта и цвета; 1 draw call на машину (`KIT.merge`) |
| лес | 9 216 елей в чанках по 4,8 м (`KIT.Field`), дальние чанки — упрощённая ель (5 треугольников) | 400–480 тыс. → 210–320 тыс. треугольников |
| персонаж | Worker by Quaternius (CC0) со скелетом, 4 клипа | готовые анимации; через `model.mjs`: 1,34 МБ → 207 КБ, 13 draw calls → 1 |
| HUD | Canvas2D поверх WebGL, те же блоки, что в 2D | чёткий текст на любом экране, координаты как у симуляции |
| эндкард | мир затемняется в 3D, лесоруб машет на пне, текст и кнопки — HUD | живой 3D-эндкард без отдельной сцены-видео |
| проверка | `probe.mjs` (цифры по QA-состояниям) + smoke-тест + demoCheck | меньше скриншотов → дешевле по токенам |
